| 관점 | 내용 |
|------|------|
| **문제** | 이미지가 글 내용과 따로 놀았다. 상징물만 그리고, 예시 문장의 색(teal/orange)이 섞이고, 점토 3D 화풍이 반복됐다. 관련성 확인 장치가 없었다. |

| **기능·UX 효과** | 운영 #42~#44 관련성 평균(19장) 3.05 → 3.89. #43 2.3 → 4.0, #44 3.2 → 4.0, #42 3.6 → 3.71. 19개 장면 모두 대상 포함. 화면에 장면별 점수·이유·대상과 "이미지 세트 다시 만들기" 버튼. |
| **핵심 가치** | 이미지가 글을 설명하는지 사람이 일일이 보지 않아도 점수로 확인하고, 낮으면 자동으로 고친다. 글당 추가 비용 최대 약 $0.14. |

## 4. 남은 항목

### 4.1 다음으로 넘기는 것

| 항목 | 이유 | 방법 |
|------|------|------|
| 개념이 여러 개인 소제목의 장면 (#42 3점 2장) | 한 장면에 개념 여러 개를 담으면 일부만 보인다 | 다음 사이클: 소제목의 개념이 2개 이상이면 대표 1개만 anchor로 고르게 하거나, 3점도 재생성 대상(`IMAGE_SCORE_MIN=4`)으로 시험 |
| 화면 확인(배지·버튼) | 미리보기가 Vercel 로그인 뒤라 열지 못함 | 운영 화면에서 직접 확인. API는 운영에서 400·404·200 확인 |
| 재시도 경로 실측 | 실측에서 3점 미만이 없었음 | `IMAGE_SCORE_MIN=5`로 1회(약 $0.12) |

### 4.2 그대로 둔 것
- 장면별 재생성 횟수 제한 없음 (기존 기능, 1회 $0.03 + 채점)
- 다시 만들기 버튼은 READY에서만 보임 (서버는 멈춘 IMAGES 단계도 받음)
- 다시 만들기 전 이미지 목록 백업 없음 (활동 기록에 이전 평균만 남김, 이미지 파일은 Blob에 남음)

## 6. 회고

### 6.1 잘된 점
- 운영 글 JSON으로 DB 없이 계획·채점·생성을 실측해, 테스트로는 못 찾을 채점 잘림 버그를 Do 단계에서 잡았다.
- 기존 이미지를 먼저 채점해 기준점(#42 3.6, #43 2.3, #44 3.2)을 만들어 개선 폭을 숫자로 보였다.
- gap-detector와 code-analyzer를 함께 돌려, 설계 일치(94.8%)만으로는 안 보이는 비용·동시성 문제를 찾았다.

### 6.2 아쉬운 점
- 로컬 DB 설정이 운영을 가리킬 수 있어 HTTP·화면 검사를 배포 뒤로 미뤘다.
- 색·재질 금지를 처음엔 AI 지시로만 두어 3건이 샜다.

### 6.3 다음에 해볼 것
- 로컬 검사용 SQLite 시드 스크립트(`DATABASE_URL` 없이 운영 글 사본 넣기)를 만든다.
- AI가 지켜야 하는 규칙은 처음부터 코드 검사도 함께 둔다.

## 8. 변경 기록

### v1.0.0 (2026-10-18)

**추가:**
- 이미지 관련성 채점(1~5점, 이유)과 3점 미만 자동 재생성
- 장면별 anchor(글 속 실제 대상), 글 종류별 화풍
- `POST /api/posts/:id/images/rebuild`와 화면의 "이미지 세트 다시 만들기"
- 환경변수 `IMAGE_SCORE_MIN`, `IMAGE_MAX_RETRIES`, `IDEOGRAM_RETRY_SPEED`, `IMAGE_MAX_REBUILDS` (모두 선택)

**변경:**
- 장면 규칙: 상징물 하나 → 글 속 대상 중심, 색·재질은 화풍이 결정
- 장면별 재생성이 파이프라인 잠금을 사용(처리 중이면 409)

**수정:**
- 이미지 다운로드·저장이 실행 시간 제한을 넘길 수 있던 문제
- 괄호가 든 이미지 주소가 본문에서 지워지지 않던 문제
