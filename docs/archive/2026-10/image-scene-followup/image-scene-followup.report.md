### 1.3 전달한 가치

| 관점 | 내용 |
|------|------|
| **Problem** | 운영 소제목 장면의 3분의 1이 빈 노트·체크리스트·폴더였다. 채점은 4.22로 높지만 눈으로 보면 16장 중 11장이 뜻이 안 보였다. "지금 무엇을 하면 되나요?" 같은 할 일 소제목은 13장 중 10장이 종이·키보드였다. |
| **Solution** | 할 일 소제목은 첫 번째 할 일을 실제 대상에 하는 장면으로, 종이 장면은 글당 1장(문서가 주제일 때만). 할 일 소제목의 종이와 글의 두 번째 종이는 코드로 찾아 그 장면만 한 번 다시 계획. 표지는 서버 랙 대신 이 글만의 대상. |
| **Function/UX Effect** | 같은 소제목 14장에서 "분명" 2 → 9장. 서버 점검 → 서버 포트에 케이블 다시 꽂는 손, 무엇을 준비 → SD 카드 꽂는 손. 계획 10개 글에서 종이 장면 글당 2.2 → 0.1. |
| **Core Value** | 채점기가 못 보는 문제를 눈 점검으로 재고, 세트 전체가 아니라 바뀐 소제목만 그려 비교했다(5번 교훈, 비용 $0.84). |

| # | 기준 | 상태 | 근거 |

| SC-4 | 2회 채점 3점 이하가 늘지 않음 | ✅ | 4 → 1, 평균 4.25 → 4.14 (흔들림 범위) |
| SC-5 | 검증 4단계 + 단위 테스트 | ✅ | 테스트 162/162 (새 26) |

### 같은 소제목 14장 전후

| 지표 | 기준선 (운영) | 새 장면 |
|---|---|---|
| 눈 점검 분명 / 약함 / 결함 | 2 / 11 / 1 | 9 / 4 / 1 |
| 2회 채점 평균 | 4.29 / 4.21 (4.25) | 4.07 / 4.21 (4.14) |
| 3점 이하 (2회 합) | 4 | 1 |

채점은 약한 종이 장면에도 4~5점을 줘서 개선이 점수에 거의 안 보인다. 판정은 눈 점검 기준(분명 = 소제목의 답이 그림에서 보임)으로 했다.

## 6. 회고

### 6.1 잘된 점
- 점수로 안 보이는 문제를 눈 점검 표(분명·약함·결함)로 숫자화했다(16장 중 11장 약함).
- 감지 함수를 운영 142개에 먼저 돌려 오탐 2종(옆 소품, 화면 page)을 이미지 전에 잡았다.
- 바뀐 소제목만 그려 비교해 5번보다 적은 비용($0.84)으로 효과를 분명히 봤다(분명 2 → 9).
- 계획만 실측을 2번 돌려 결과가 흔들리지 않는지(종이 1 / 0) 확인했다.

### 6.2 아쉬운 점
- 1회차 계획 실측이 장면 전체(style·must·avoid)를 저장하지 않아 2회차를 다시 돌렸다(Claude 비용 추가, 소액).
- 종이를 막자 "배송 상자"가 새 기본값처럼 나오기 시작했다. 하나를 막으면 다음 안전한 소품으로 옮겨간다.
- 이미지 모델이 기기 표면에 넣는 글자는 장면 규칙으로 막을 수 없다.

### 6.3 다음에 해볼 것
- 계획 실측 스크립트는 처음부터 장면 전체를 저장한다.
- 소품 반복은 "금지 목록"이 아니라 글 안의 소재 다양성(같은 소품 2번 금지)으로 다루는 쪽을 검토한다.
