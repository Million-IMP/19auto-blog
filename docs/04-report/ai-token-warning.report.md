### 1.3 전달한 가치

| 관점 | 내용 |
|------|------|
| **Problem** | 모델의 생각 토큰도 길이 제한에 들어가 응답이 예고 없이 잘렸다(이미지 계획 4번 중 1번). AI 호출 11곳 중 3곳(수집 처리·OSMU·3줄 요약)은 잘림을 확인하지 않아 반쯤 쓴 글이 저장될 수 있었다. |
| **Solution** | 모든 AI 응답이 `checkResponse`를 거쳐 사용량을 재고, 80% 이상이면 활동 기록(호출별 하루 1번, 실제 잘림은 매번)과 서버 로그에 남긴다. 3곳도 잘리면 오류. |
| **Function/UX Effect** | 활동 기록 "오류" 탭에 "AI 길이 경고"가 보인다. 잘린 OSMU·요약·빈 OSMU가 저장되지 않고, 요약 실패 시 원인이 화면에 보인다. |
| **Core Value** | 길이 제한을 감으로 올리지 않고 실제 사용량 기록을 보고 필요한 호출만 올린다. |

## 6. 회고

### 6.1 잘된 점
- 계획 전에 AI 호출 11곳을 표로 정리해 경고만이 아니라 조용한 잘림 3곳을 찾았다.
- 바뀐 오류가 크론을 멈추지 않는지 호출부를 직접 확인했다.

### 6.2 아쉬운 점
- 처음 설계의 하루 1번 중복 방지가 정작 중요한 "실제 잘림"을 가릴 수 있었다(검수에서 발견).
- 첫 테스트가 24시간 조건을 실제로 확인하지 않았다.

### 6.3 다음에 해볼 것
- 중복 방지 같은 걸러내기 규칙을 만들 때 "가장 중요한 경우가 걸러지지 않는지"를 설계에서 먼저 따진다.
