### 1.3 전달한 가치

| 관점 | 내용 |
|------|------|
| **Problem** | v1 후 #42가 3.71. 3점 장면은 대상이 개념 여러 개(블루투스·LAN·인터넷)이거나 흐리게 그려야 하는 화면 속 내용이었다. 흐림 규칙과 채점 기준도 부딪혔다. |
| **Solution** | 대상은 개념 하나·눈에 보이는 사물이나 행동, 화면은 배경으로만. 나열한 대상은 코드로 찾아 한 번 다시 계획. 채점은 흐린 글자·화풍 색만 감점 제외. |
| **Function/UX Effect** | 로컬 계획 #42: 7/7 장면이 대상 하나(지문 센서에 댄 손가락, 노트북과 무선 스피커 등). 이미지 계획 잘림 실패(4번 중 1번)를 없앰. |
| **Core Value** | 점수 부풀리기를 숫자로 걸러냈다: 채점 기준만으로 3.71 → 3.93임을 먼저 재고, 목표를 2회 평균 ≥ 4.2로 올렸다. |

## 3. 완료 항목

### 3.1 기능 요구사항

| ID | 요구사항 | 상태 |

### 3.2 계획 밖 수정

| 수정 | 이유 |
|------|------|
| planImages 8000 → 16000, replanScene 1500 → 4000 토큰 | 생각(thinking) 토큰이 길이 제한에 포함되어 #42 계획이 4번 중 1번 잘림. 응답 5,578~8,469 토큰 |
| 다시 계획 실패 시 원래 장면 유지, 30초 미만이면 건너뜀 | 실패 하나로 계획 전체가 버려지고 크론이 건너뛰어 글이 멈춤 |
| 계획 없는 IMAGES는 120초 이상 남았을 때만 시작 | POLISH 직후 20초 남은 상태에서 시작해 시간 초과로 멈추는 위험(v1부터) |

## 6. 회고

### 6.1 잘된 점
- 3점 이유 문장을 표로 모아 원인이 두 가지(나열, 화면 속 내용)임을 먼저 밝혔다.
- 채점 기준만 바꿔 다시 채점해(3.71 → 3.93) 기준 변경 효과와 실제 개선을 나눴다.
- 계획만 하는 로컬 실측으로 생각 토큰 잘림을 배포 전에 찾았다.

### 6.2 아쉬운 점
- v1에서 planImages 출력 토큰을 재지 않아 잘림 위험을 놓쳤다.
- 채점은 같은 이미지도 ±1 흔들려 한 번 채점으로는 판단이 어렵다.

### 6.3 다음에 해볼 것
- AI 호출 응답 토큰이 상한의 80%를 넘으면 경고를 남긴다.
- 효과 검증은 처음부터 2회 이상 채점한다.

## 8. 변경 기록

### v1.0.0 (2026-10-18)

**변경:**
- 장면 대상: 개념 하나, 눈에 보이는 사물·행동. 화면 속 내용은 대상 금지
- 채점: 흐린 화면 글자·화풍 색은 감점하지 않음(대상이 화면 자체가 아닐 때)
- 나열한 대상(`·`, `ㆍ`, 쉼표, `및`)은 그 장면만 한 번 다시 계획

**수정:**
- 이미지 계획이 길이 제한에서 잘리던 문제 (8000 → 16000 토큰)
- 장면 다시 계획 실패나 시간 부족으로 글이 멈추던 문제
